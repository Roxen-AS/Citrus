# Citrus glass materials and physical feedback — design

Design authorized by the user’s explicit Liquid Glass request. Primary design input is the user's complete `docs/design/apple-design.md`, read before inspecting implementation. This bounded subproject translates its response, interruptibility, hierarchy, typography and accessibility principles to the existing Windows WPF app. It follows the already authorized SDD workflow; it does not restart approval or implement code. Original source inspection used `0567689fc829a684f24e1c970eadf8a9da6ea588`. The parent now reports primary baseline `17aae78`, including window-work-area fitting and screenshot-helper fix 1; integrate the reviewed helper fix 2 (`8bed` prefix) before execution. These fixes have no UI API changes; compose with their current SourceInitialized/capture helpers. Editor foundation work remains independent and consumes these shared resources later.

## Recommendation and alternatives

Use documented Windows 11 system Acrylic for eligible nonlayered HWNDs, composed with original restrained WPF highlights, solid functional surfaces and globally batched critically damped responses. For the layered wheel, prove a dedicated native Acrylic companion behind the existing OLE window; retain an honest solid material fallback whenever that arrangement is unsupported or fails native evidence. This is a Citrus interpretation of Liquid Glass, not Apple's proprietary renderer or a claim of optical equivalence.

Three approaches considered:

1. **Recommended: native system backdrop plus original surface treatment.** Real behind-window frosting on eligible Windows 11 builds; keep WPF and the existing drag protocol. A separate wheel companion isolates DWM from the layered OLE HWND. Cost: native placement/lifecycle and actual compositor verification are required.
2. **Nonlayered replacement wheel or framework rewrite.** Could unify input/backdrop in one compositor window, but changes genuine OLE registration, shaped transparency and window creation. It is a separate interaction rewrite and conflicts with this bounded project's preservation requirement.
3. **Alpha panels or desktop screenshot blur.** Alpha tint alone does not frost the backdrop; screenshot textures are stale, capture unrelated user content and add input/render cost. Neither is an acceptable implementation or evidence substitute.

## Non-negotiable constraints

- Windows 10 22H2/11 x64; native WPF; no framework rewrite, new runtime backend download, undocumented composition API or desktop-as-texture capture.
- Genuine layered OLE wheel HWND, confirmed immutable payload, generation/arming/paging/drop/cancel ownership and fixed visible target geometry remain unchanged.
- Backdrop HWNDs never activate, receive keyboard focus, register OLE, capture pointer input, or outlive their visible surface. Unconfirmed candidates never show a backdrop or material shell.
- Windows high contrast or disabled transparency effects always uses opaque accessible materials; user ReduceTransparency also forces opaque materials. Reduced motion is independent from transparency and sound.
- One application CompositionTarget.Rendering subscriber exists only while spring channels are active; no perpetual idle animation loop or animated software blur.
- RenderTargetBitmap is WPF-layer evidence only. Actual OS backdrop requires native compositor capture over an owned background, or explicitly pending manual Windows 11 evidence.

Use `DWMWA_USE_IMMERSIVE_DARK_MODE=20` for theme where supported. Check HRESULTs; no dependency on SetWindowCompositionAttribute, undocumented ACCENT_POLICY or a registry-only transparency signal. Successful HRESULT means configured, not visual proof that OS policy is currently showing blur.

For ordinary windows, keep AllowsTransparency=false and the native nonclient frame. ## Wheel companion: ownership, geometry and eligibility gate

Create at most one raw native nonlayered WS_POPUP Acrylic companion for the resident wheel, on the same UI thread. It uses WS_EX_NOACTIVATE|WS_EX_TOOLWINDOW|WS_EX_TRANSPARENT and WS_DISABLED, no OLE registration, and WM_MOUSEACTIVATE→MA_NOACTIVATE / WM_NCHITTEST→HTTRANSPARENT. WS_DISABLED is the input exclusion mechanism (WindowFromPoint skips disabled windows); paint-order transparency is not the mechanism. **WS_EX_TRANSPARENT is not a general cross-thread input-pass-through guarantee, and HTTRANSPARENT only forwards within the same thread.** Safety relies on disabling the companion and keeping its complete window region covered by the existing real OLE capture HWND above it. Do not place any interactive control on it.

A companion owned by the wheel cannot sit behind it: Win32 owned windows stay above their owner. Instead, own the companion with a dedicated hidden nonactivating resident lifetime HWND; do not use MainWindow (minimizing Home must not hide wheel material). The existing wheel stays unowned and unchanged. Position the topmost companion immediately behind the topmost wheel using documented SetWindowPos/DeferWindowPos with NOACTIVATE and an update/reentrancy guard. Never make the companion the wheel's owner or flip AllowsTransparency/WS_EX_LAYERED on an existing wheel/candidate. The hidden lifetime owner remains hidden and has no OLE registration.

Clip the companion using SetWindowRgn to the physical-pixel ellipse corresponding to the current 352×352 DIP shell at (8,8), entirely inside the existing 368×414 wheel bounds. Region ownership passes to Windows after successful SetWindowRgn; delete temporary regions only on failure. The overlay's caption, hint and page-arrow area below the ellipse receives solid WPF pill backgrounds, not a second glass layer. Only the shell ellipse is in the native region; no rectangular caption extension or helper outside it. Thus the companion has no uncovered strip outside the OLE window, including at fractional DPI. Derive scale from the actual wheel HWND DPI and final native rectangle after work-area clamping; round the companion region inward when necessary. No WPF logical/physical mixing or independently predicted monitor anchor.

Before enabling wheel native mode, Task 1 must prove on an actual supported Windows 11 compositor that the **nonlayered, disabled, clipped, behind-layered-window** configuration produces real backdrop frosting without a rectangle, activation or input interception. SetWindowRgn/DWM interaction is not guaranteed merely by the APIs existing. If clipping causes DWM to suppress material, keep the wheel solid and document that specific limitation; do not remove the clip, use an undocumented blur API, fake a desktop texture, or rewrite the wheel to make a screenshot look successful. Ordinary-window native Acrylic remains independently usable. Native helper artifacts include foreground HWND, styles, owner, z-order, regions, build and HRESULTs plus actual compositor captures.

Wheel lifecycle, all marshaled on Dispatcher:

1. Candidate/unconfirmed: companion hidden, no material visual, original capture HWND remains live for genuine admission.
2. Confirmed presentation: first render the full fixed WPF shell/petals at opacity 1 with opaque fallback material; input geometry is immediately usable. Prepare the still-hidden companion at final bounds/region/z-order. After that actual WPF presentation is ready, show the companion behind the complete shell with NOACTIVATE, then switch only the shell tint to the native material at a rendering boundary. The full functional wheel is always present before any OS glass can become visible. A canceled generation aborts this sequence. On configuration failure, never show the companion and retain solid material. No native position call occurs on steady DragOver.
3. Mode/page change: retain both HWNDs/anchor and immutable payload; reset native selection/arming exactly as today; companion geometry changes only if actual placement/DPI changes, not slot count or hover.
4. Drop, Escape, drag leave, pause, global unconfirmed release, timeout, dismissal or preparation failure causing teardown: synchronously disable/end the accepting session and hide both companion and wheel. There is no top-level opacity/scale exit animation or delayed root hide in this project; remove the old 100-ms dismissal clock while retaining generation-safe cleanup. Existing post-OLE submission deferral remains unchanged. This deliberately prevents a bare frosted circle lingering beneath disappearing WPF controls.
5. Reopen during queued cleanup or an internal emphasis response: generation invalidates stale completion; reset/update the same hidden companion and retarget eligible child visual values from their current presentation state. A callback for an older generation may never hide the reopened pair.
6. WM_DPICHANGED/WM_WINDOWPOSCHANGED: schedule/coalesce final positioning after WPF updates its transform; hide companion while bounds mismatch, update from actual HWND placement, then show only if the current generation is still confirmed/visible. Preserve anchor/clamping; never animate native placement.
7. Effects/high-contrast/theme/session change: settle visual state, hide companion, apply new policy/material, recreate only native helper resources when necessary. High contrast/ReduceTransparency removes companion synchronously; disabling motion alone does not remove eligible glass.
8. Hide/Close/quit/exception: idempotently hide/dispose helper and remove hooks; destroy visible companion before lifetime owner. No static delegate or Rendering subscription retains disposed windows. Wheel failure must not strand helper HWNDs.

## Immediate input feedback and analytic springs

Use the guide's critically damped default, with no idle oscillation or momentum simulation for the pointer wheel. The new subproject supersedes the interface spec's fixed 160/90/100-ms presentation durations only; input timers and the 45-ms audio selection throttle are unchanged.

A `SpringState` stores current value, velocity in units/second and target. For damping ratio 1.0, response r seconds defines omega=2π/r; it is a natural response parameter, not duration. With displacement d=x−target and c=v+omega×d, exact advancement for elapsed t is x'=target+(d+c×t)exp(−omega×t), v'=(v−omega×c×t)exp(−omega×t). Retarget first advances to the input event's monotonic timestamp, then changes only target, preserving displayed value/velocity. Independent x/y channels would have independent velocity; this project does not add moving-window or fling gestures.

Default Response=0.34 s, DampingRatio=1.0; press-release emphasis 0.30 s; chrome/content reveal 0.38 s. Snap to target and velocity zero when both |x−target|≤0.001 and |v|≤0.01 for normalized channels (DIP channels, if used, ≤0.05 DIP and ≤0.5 DIP/s). A >250-ms frame gap settles to the target immediately; never replay missed frames after suspend. Validate finite inputs and response 0.05..2 s. Retained velocity can cross a new target even at critical damping; clamp applied opacity to 0..1 while preserving the finite physical channel state, rather than assigning an invalid WPF value. Only critical damping is implemented; do not expose an unsupported bounce control.

One App-owned `SpringAnimator` batches all active channels in one CompositionTarget.Rendering callback and unsubscribes when none remain. Retarget does not allocate a new Storyboard/clock; retain per-element channels. Apply only local brush opacity, element opacity and visual-only child RenderTransform; never animate Width/Height/Margin, HWND position, blur or shared global brush instances. Dispose/cancel by owner; high contrast/reduced motion settles immediately and removes all channels/subscription.

Buttons provide synchronous IsPressed/keyboard-down fill/edge feedback (commit still uses normal Click/release; moving away cancels as native Button does). Optional child-content scale 1→0.985 while pressed; root hit area/focus border stays fixed. Release retargets from current value/velocity; rapid down/up/down must not jump or lock input. For wheel targets, immediately change logical selection/solid fill/caption; spring a small specular intensity from current value, with no scale/translation of petal outlines. Whole-wheel .94→1 scale and root opacity entrance/exit are removed because visual targets would disagree with hit geometry or expose a bare native backdrop. Keep structural shell/petals steady; animate only child content/emphasis inside that complete chrome. Never animate WPF Window.Opacity on native-backdrop windows (it can require layered-window behavior), call SetLayeredWindowAttributes on the companion, or recompute native regions per frame. Noninteractive central thumbnail may use .97→1 plus opacity; fixed shell/targets appear at their final geometry. Hide/cancel has no input-blocking animation wait.

Keep existing FeedbackAudio and SoundEnabled=true default/mute. Emit open/selection/success/error only from their current causal state transitions, not spring ticks or completion; audio and logical visual feedback start in the same dispatcher turn. No sound replay on theme, DPI, policy refresh or retarget. Reduced motion and reduced transparency never silently mute or unmute.

## Exact component and preference contracts

- `SpringAnimator.Retarget(object owner,string channel,double target,SpringParameters parameters,Action<double> apply):void`; `SetImmediate(object owner,string channel,double value,Action<double> apply):void`; `CancelOwner(object owner,bool settle):void`; `Dispose()`. Channel creation requires SetImmediate before first Retarget; SetImmediate stores Value=Target=value and Velocity=0, cancels any active response for that channel and applies the value synchronously; preserve current state on subsequent retargets; weak/explicit owner lifecycle avoids static retention. Settlement applies the exact target synchronously, sets velocity zero, removes it from the active set while retaining its settled value for future retargets, and unsubscribes Rendering when the last active channel settles. CancelOwner and Dispose remove retained owner/channel state as well. CancelOwner(settle:true) applies each target before removal; settle:false removes without another apply. Dispose removes subscriptions/channels without callbacks into destroyed visuals. There is no completion/hide callback contract: window hiding is synchronous and independent of spring completion. Internal `AdvanceAt(long stopwatchTimestamp)` supports deterministic tests without a second production rendering loop.
- `PressFeedback.IsEnabled` attached boolean on ButtonBase uses retained content transform and existing IsPressed semantics. Tests assign a deterministic scheduler explicitly, including resource-only DesktopFixture construction without App.Startup. On Unloaded or scheduler replacement, cancel this button owner on its old scheduler, detach handlers as applicable and restore template state.
- `MaterialSurface` is a lightweight Decorator with dependency properties `Role:MaterialRole (Chrome,WheelShell,Toast)`, `State:BackdropState`, `CornerRadius:CornerRadius`; it has no native window or rendering clock. Bind State to that specific window/shell controller result, never a global native-enabled boolean or an alpha brush. Ordinary windows may be ConfiguredNativeAcrylic while the wheel companion remains Solid; the wheel must then keep opaque shell resources.

Add `CitrusSettings.ReduceTransparency=false`; old settings deserialize with this default and retain existing SoundEnabled/remaps. Settings displays “Reduce transparency” separately from “Reduce motion” and sound. Effective system restrictions override the preference, with concise explanatory text. App creates one policy monitor and animator, supplies controllers and the inheritable PressFeedback.Animator property on each window root, then clears those root properties/cancels owners and disposes the shared services before resident shutdown; future editor windows reuse Attach/resources rather than copy code.
