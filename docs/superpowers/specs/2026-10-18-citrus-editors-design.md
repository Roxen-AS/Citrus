# Citrus functional editors — specification

2026-10-18. This follows the interaction/interface project; preserve its drag protocol. This independently deliverable subproject uses the existing Magick, FFmpeg and PDF stack. It is not a claim of measured proprietary Tangerine numeric equivalence or complete reference parity. Evidence: the interface research reports in the ignored execution workspace and the permanent `docs/tangerine-parity.md`; current `Models.cs`, `SubmissionService.cs`, `BatchRequestBuilder.cs`, `OutputWriter.cs`, `MediaProcess.cs`, `EngineRegistry.cs`, and `ToolOptionsWindow.xaml.cs`.

## Scope and invariants

- Windows 10 22H2/11 x64; .NET 10.0.402 and native WPF; offline processing; no runtime engine/model downloads.
- Originals remain unchanged; export uses collision-safe `OutputWriter`; no preview writes into the user's output directory.
- Preview and export compile the same immutable recipe and operation order; export always renders from verified source copies, never the viewport bitmap.
- Core recipes contain no WPF objects, mutable lists, arbitrary command strings, or decoder handles. Schema version 1; explicit allowlisted JSON discriminators; unknown versions/types fail visibly.
- Opening, previewing, undoing and canceling an editor never enqueue work. Export queues a frozen document once; subsequent edits cannot change that job. Retry uses the same frozen recipe and verified sources.
- Every visible enabled control changes a genuine preview, recipe or output. Missing capabilities remove the corresponding action and explain why; no synthetic waveform, guessed file size or successful placeholder inference.
- Keep existing operation IDs and scalar routes working. New typed routes are distinct until a compatibility adapter is verified. All desktop/wheel entry points ultimately use the same queue and output writer.
- This project includes manual image/video redaction. OCR, face detection/tracking, automatic speech detection, subject-background removal and Office reconstruction remain explicitly gated separate projects.

## File and ownership boundaries

`src/Citrus.Core/Editing/` owns immutable contracts, finite/bounds validation, undo history, compression targets, capability descriptors, and typed submission assembly. `src/Citrus.Conversion/Editing/` owns verified source staging, renderer dispatch, image composition, media graph compilation/binary decode, PDF plans, metadata and measured export. `src/Citrus.Windows/Editors/` owns family views/view-models, input gestures and playback sink. Share the interface project's Tokens/Controls/Icons, FilePreviewService, jobs and toast rather than creating a second theme or resident.

One focused file per contract/service listed below. New `ImageEditorEngine`, `MediaEditorEngine`, `PdfEditorEngine` implement existing `IConversionEngine`. Each family engine adapts its typed document to the shared renderer and `OutputWriter`; it does not become a second queue. A separate `CollageEditorEngine` may share ImageRecipeRenderer utilities while owning its grouped capability. `EngineRegistry` composes them only after actual route capability probes pass.

A family renderer may return a warning when viewport downsampling approximates the full-resolution result; it cannot change the meaning of controls.

Service interfaces:

- `ISourceSnapshotService.CaptureAsync(ImmutableArray<string> paths, CancellationToken ct) : Task<ImmutableArray<SourceCaptureResult>>` captures off UI, returning one ordered result per requested path; hash/read failure returns Error with no snapshot, no invented ID/hash/document. Cancellation throws and releases all owned work rather than returning partial success as a completed capture.
- `ISourceSnapshotService.StageVerifiedAsync(ImmutableArray<SourceSnapshot> sources, string privateDirectory, CancellationToken ct) : Task<ImmutableDictionary<Guid,string>>` copies while hashing, checks expected hashes and returns only verified private paths. Export/preview workers render those immutable staged bytes; path/mtime alone are not sufficient.
- `EditorRecipeValidator.Validate(EditorDocument document) : ImmutableArray<ValidationIssue>` validates IDs, field bounds, source references and family limits; engines revalidate after staging/probing.
- `IEditorRenderer.RenderPreviewAsync(EditorDocument document, PreviewRequest request, CancellationToken ct) : Task<PreviewFrame>`.
- `IEditorRenderer.RenderExportAsync(EditorDocument document, string privateDirectory, IProgress<ConversionProgress>? progress, CancellationToken ct) : Task<StagedExport>` writes only inside the owned directory. `EditorRenderRouter` selects a family renderer by recipe type.
- `EditorHistory.Current : EditorDocument`; `Commit(EditorDocument next, string coalescingKey) : void`; `Undo() : bool`; `Redo() : bool`; `Reset() : void`. Store at most 100 immutable states. A drag/slider gesture is one committed state; transient moves are preview-only. New edits clear redo. Revision increases on every published state including undo, independent of recipe content.
- `EditorSession.Update(EditorDocument document) : void`; `PreviewAsync(PreviewRequest request, CancellationToken ct) : Task<PreviewFrame?>`; `Close() : void`. Publish only a result whose document revision and generation both equal the latest request; superseded results return null. Close cancels preview/playback, not an already submitted job.
- `EditorSubmissionService.SubmitAsync(EditorSubmissionBatch batch, CancellationToken ct) : Task<IReadOnlyList<ConversionJob>>` validates and freezes every item before admission, then uses the existing queue; it does not call legacy `SubmissionService.SubmitAsync` or pass a document through `SubmissionChoice`. Add optional trailing `EditorDocument? Editor = null` to `OperationRequest`; add optional trailing `CompressionOutcome? Compression = null` to `ConversionResult`. Preserve existing constructors/callers. Project actual metrics through ConversionJob/JobViewModel.

The Task 1 integration seams are required constructor dependencies, with no permissive default: Core `IEditorAdmissionInspector.ValidateAsync(OperationRequest request, CancellationToken ct):Task<ImmutableArray<ValidationIssue>>` independently verifies captured sources and inspected family bounds before any item is admitted; Core `IEditorPayloadValidator.ValidateAsync(OperationRequest request, StagedExport staged, string privateDirectory, CancellationToken ct):Task` independently validates actual family format/content and throws on invalid output. `EditorSubmissionService(JobQueue, EditorRouteRegistry, IEditorAdmissionInspector)` completes inspection for every item before its synchronous admission boundary. `EditorOutputPublisher(OutputWriter, ExportTargetResolver, IEditorPayloadValidator)` runs the payload validator after generic path/shape/size checks and before OutputWriter. Task 1 leaves registry defaults empty; real family implementations must provide these checks before route registration. Test collaborators are confined to tests.

## Exact application routing and batch contract

Legacy `SubmissionChoice` has only Inputs/Options/Destination; leave it unchanged. The editor branch is selected **before** App calls legacy SubmissionService/ConfirmAsync. Rich documents must never be discarded by converting them into scalar OperationOptions.

App integration is one explicit decision tree:

1. `App.SubmitAsync(OperationDrop drop, OperationOptions? options = null, string? destination = null, SubmissionOrigin origin = SubmissionOrigin.Home)` copies the actual drop paths; retains existing busy/shutdown/post-OLE guards. Actions continue through FileActions. The wheel caller explicitly passes Wheel; Home passes Home. No editor exists inside an OLE callback.
2. If `EditorRouteRegistry.TryGet(drop.Operation.Id, out route)` succeeds, construct EditorOpenRequest with **that same descriptor and initial paths**, route.EntryTool, options or defaults, chosen destination and origin. Await host. Null means cancellation and zero jobs. Accepted batch goes to EditorSubmissionService; add each returned job to App's existing jobs/home/toast tracking exactly once. This branch never invokes ConfirmAsync. A missing renderer/host pair is not registered.
3. Otherwise retain the existing scalar SubmissionService→ConfirmAsync path. Plain conversions/actions stay quiet where already required. Legacy fallback is used only for operations not yet migrated, not after a registered editor fails. An editor failure produces a recoverable error, not a silent numeric fallback.
4. `App.RetryAsync(ConversionJob job,string? destination)` branches on `job.Request.Editor`: non-null calls EditorSubmissionService.RetryAsync directly; null retains scalar retry. Do not open an editor just to retry a valid frozen recipe. “Edit settings” is a separate command opening a new editor draft from that request. Changed/missing source or font identity requires explicit Reload/Edit, not substitution during retry.

Operation identity and execution ownership are explicit. Keep the chosen descriptor's ID, Mode, OutputExtension, IsGroup and NeedsOptions on the queued request; do not relabel `image.resize` as `image.editor`, or claim IsGroup because auxiliary images exist. `OperationRequest.Inputs` contains only that item's ordered root paths; `Editor.Sources` contains those root snapshots plus referenced auxiliary snapshots. Fonts are separate artifacts, never root inputs. Old ImageEngine/MediaEngine/PdfEngine `CanExecute` must reject `request.Editor is not null` so they cannot accidentally execute a typed job while ignoring its recipe. Typed family engines accept migrated IDs only when Editor is present and valid; their Operations expose the canonical descriptors, without inventing different flags for duplicate IDs. New operation IDs support catalog admission with null Editor but require a typed document at execution. Capability discovery is tested independently from execution admission.

New descriptors use OperationMode.Tools. OutputExtension is null for same-source-format image tools, codec-selectable compression/metadata and multi-output folders; .mp4 for fixed video/visualizer presets, .wav for fixed audio edits/join, .png for default snapshots, and .pdf for fixed PDF editors. Keep the selected export format in ExportPolicy for variable-format routes. Each new ID must be tied to a real preset and capability test before catalog exposure. Generic `.editor` is a workspace entry, not a replacement ID for legacy tool jobs. Existing `image.strip` remains a direct strip action (no forced editor); `images.pdf` stays its working group ordering/options path, including SVG support; `video.audio`, every `image.convert.*`/`media.convert.*`, subtitle/archive conversion/actions remain existing routes. Their preservation tests are required. `pdf.organize` offers the newly explicit multi-source grouped organizer; `pdf.editor` edits each root separately, so there is no implicit multi-file merge.

Batch ownership: InitialPaths is the immutable incoming selection, preserved byte-for-byte in order for the session; InitialSources contains only successfully captured initial source snapshots, in initial-path order; it need not have the same count as InitialPaths. An uncaptured input remains an error row keyed by its raw path, without a source ID or recipe. Inclusion checkboxes change IncludedRootIds and explicit ExcludedInitialPaths, never the recorded initial payload. Every initial raw path must either resolve to an included captured root or appear in ExcludedInitialPaths; the latter records deliberate exclusion even when no capture/ID was possible. Captured excluded sources may remain in InitialSources. No raw path silently disappears. Additional local file pickers create explicit Imports with Root role (add another independent file or a grouped collage/join/PDF source) or Auxiliary role (background/annotation image); they cannot masquerade as original drag items. The host displays added sources and included count. Service verifies every captured initial source belongs to Request.InitialPaths using full-path normalization and Windows case-insensitive path comparison while preserving original ordering/recorded values; accepts only the captured subset; verifies unique IDs, allowed import roles, valid references and descriptor/route shape against its own registry. Every included root occurs exactly once across PerRoot items (one RootSourceId per item); Group produces exactly one item whose RootSourceIds equals IncludedRootIds in chosen order. Removed roots remain recorded but are not submitted. Unreferenced auxiliary inputs are excluded from each document. Group destination requirements examine participating **root** folders; auxiliary/font file locations do not force a destination change. PerRoot outputs default beside each root.

Pre-admission policy is deliberately explicit: any included root with capture, inspection or mapping errors blocks Export. The host keeps its error visible and offers Reload or an explicit inclusion checkbox to exclude it; it never silently excludes an input, invents a hash/recipe, or manufactures a queued failed document. A captured-but-uninspected root may appear in InitialSources but cannot appear in an accepted item's RootSourceIds until inspection succeeds. Each IncludedRootId must resolve to a successfully captured, inspected source with a valid mapped document; referenced auxiliary inputs/fonts must likewise be ready or explicitly removed/replaced. Unknown/uncaptured IDs and incomplete documents are rejected by service validation. Validate every user field and accepted item before any enqueue. Cancellation before admission queues nothing; after admission begins, finish admitting the already frozen batch synchronously so cancellation cannot silently truncate its roots. Once admitted, independent jobs can fail normally during source re-verification, decoding, encoding or publication without canceling successful siblings. The scalar legacy SubmissionService retains its existing per-input inspection-failure jobs and partial-success behavior; this richer editor admission policy does not change it.

Image batches use `ImageBatchGeometry = Relative, Pixels` and `ImageResizeIntent(int? Width,int? Height,bool PreserveAspectRatio,bool AllowUpscale)` and `ImageBatchTemplate(EditorDocument Document, SizeI RootSize, ImageBatchGeometry Geometry, ImageResizeIntent? Resize, bool CopyLayers, bool PreserveSourceFormat)`. `ImageBatchMapper.Map(ImageBatchTemplate template,EditorDocument target,SizeI targetNormalizedSize):EditorDocument` produces an independent immutable image document using the target's existing root ID, sources and unmodified per-file layers; it never copies the template root ID onto another root. Scalars/quarter-turns/metadata intentions apply identically. Default Relative crop maps its fractions in the post-rotation plane to each root, then applies specified pixel rounding; Pixels uses the same exact bounds and fails validation where they do not fit. Resize intent retains optional width/height and aspect choice rather than copying the first image's computed dimensions. Mapper resolves each target's concrete ImageGeometry.OutputSize from that intent: with one dimension and PreserveAspectRatio, derive the other from the target crop; with both and PreserveAspectRatio, contain within the bounding box; with both and no preservation, use the exact dimensions. Without Resize intent, preserve the target's existing output size unless the user chooses a common explicit canvas. Legacy image.resize initializes AllowUpscale=true to retain existing resize capability; new crop/canvas defaults keep no-upscale policy. Source masks map in source-plane fractions; annotation coordinates map in final-canvas fractions only when CopyLayers is explicitly selected, scaling stroke/font/radius by the geometric mean of x/y scale. Default CopyLayers=false preserves the target document's existing annotations/masks and their referenced sources/fonts; explicit CopyLayers=true replaces them with the mapped template layers. This is why Map receives the existing target document, not only its SourceSnapshot. Fixed-size canvas annotations remain at the same canvas pixels. Auxiliary image IDs and captured fonts may be shared immutably. PreserveSourceFormat=true resolves each root's original supported format; false uses the explicitly selected common format. Output stems are derived separately from each root plus the entry-tool suffix. The host offers “Apply settings to all” with Relative/Pixels and explicit “Include layers”; highlighting a different preview file never applies or excludes anything.



## Output shape and publication authority

`ExportTargetResolver.Resolve(OperationRequest request):ExportTarget` uses the canonical operation/recipe contract and validated ExportPolicy; request.Editor must be present. `EditorOutputPublisher.PublishAsync(OperationRequest request,StagedExport staged,string privateDirectory,CancellationToken ct):Task<ConversionResult>` checks staged.Shape against that target before touching the destination. The renderer chooses only an allowlisted format for its family/mode and returns relative payload members, never an absolute destination, user-output path or arbitrary extension.

Shape is semantic: ordinary image/collage/audio/video/snapshot/PDF/text exports are File; video splits, PDF PageImages and PDF SeparatePageDocuments are Directory **even with one output member**. File requires exactly one member. Directory requires at least one member; Files.Length cannot change its shape. The target resolver maps FormatId through the route's trusted format table (jpg→.jpg, jpeg→.jpeg, tif→.tif, tiff→.tiff, png→.png, pdf→.pdf, and the remaining explicit route entries). File's Extension is that mapped suffix; Directory's Extension is null and contained members use the permitted format suffix. Source-format defaults are resolved explicitly per root before acceptance and still checked against the format allowlist; retain allowed original suffix aliases such as .jpg/.jpeg and .tif/.tiff through distinct FormatId aliases backed by the same encoder. Do not silently rename a source-format edit to a different extension spelling. Current operation descriptor identity/OutputExtension is preserved for compatibility but cannot override the typed recipe's validated output shape.

DestinationDirectory is an explicit absolute chosen folder, or the root's parent for PerRoot; Group uses the validated common-root parent or explicit folder required by mixed roots. Root paths come from OperationRequest.Inputs, never auxiliary/fonts or a renderer's first file. OutputStem is a single filename component from the host's root-derived default or user's explicit name; reject empty, dot/dot-dot, separators, rooted names, NUL/control/Windows-invalid characters, colon/ADS, trailing space/dot and Windows reserved device basenames. Append exactly the trusted extension for File; never treat OutputStem as a path or infer an extension from it. The host displays the final proposed name. Actual collision suffixes remain exclusively OutputWriter's responsibility.

Within the owned privateDirectory, renderers place deliverables in `payload/`, sources in `sources/` and scratch in `work/`. StagedOutput.RelativePath is a single relative leaf filename under payload, with the same filename checks and required member extension; this project has no nested output bundles. Reject absolute/traversing/duplicate/case-colliding names, symlinks/reparse points and any unlisted file/directory inside payload. Check every listed file exists, its measured size equals Bytes, and family-specific independent format validation succeeded. Do not copy sources/work or font files. Publisher copies the validated file/set into OutputWriter's destination-side staging, then invokes collision-safe File or Directory commit according to Shape. Renderer scratch location does not choose the final destination. Cancellation or any member failure publishes nothing; existing destinations remain intact.

## Image contracts and rendering

All visual image tools accept validated single-frame raster inputs; SVG stays conversion-only. Normalize EXIF orientation once, convert embedded ICC to SDR sRGB once, then flip/rotate, crop, tonal/detail adjustments, destructive masks, place into canvas, annotate and encode. Geometry uses top-left, pixel-edge coordinates in the normalized source plane; the renderer supplies source→transformed→canvas matrices. Crop is stored in the post-flip/rotation plane, with the transform defined by the same recipe. Changing rotation maps the crop through the transform or requires explicit Reset crop; never silently crops a different area.

Crop floor(left/top), ceil(right/bottom), clamp; reject empty/outside input. Exact output dimensions resample only after the crop; default no upscale. Ratio presets 1:1, 4:3, 3:2, 16:9, free, custom positive ratio; UI shows final rounded pixel bounds. Canvas backgrounds do not remove opaque subject backgrounds. Shadows are clipped to the explicitly sized canvas. Collage distributes remainder pixels deterministically in input order; every tile + margin + gap fits exactly. Grid rows are ceiling(count/columns); last-row empty cells remain background. Featured fraction 0.2–0.8.

Adjustment v1 defaults: identity (all zero except Gamma=1, Saturation=1); exposure −5..5 EV; gamma 0.1..5; saturation 0..2; hue −180..180; brightness/contrast/highlights/shadows/vibrance/warmth/tint/vignette −1..1; clarity/dehaze/sharpen/denoise/grain/effect amount 0..1; blur sigma 0..100 source px. Use the formulas in the backend research for exposure/brightness/contrast/gamma/highlight/shadow/saturation. Pin the remaining v1 algorithms in golden fixtures: clarity is luminance unsharp with Gaussian sigma=12 source px and amount=Clarity; dehaze uses a 15×15 dark channel, atmospheric light from the brightest 0.1% dark-channel pixels, transmission max(0.1,1−0.95×Dehaze×dark(normalized RGB/A)); identity short-circuits at zero. Warmth/tint are artistic channel gains, not Kelvin white balance. Denoise is median radius 1..3 selected by strength then blend by strength. Grain is coordinate-hashed noise using the saved seed, never fresh randomness per preview. Q8 output is SDR; do not claim HDR/high-bit-depth fidelity. Scale spatial radii with render scale. A 100% source tile is the fidelity check for detail and compression.

Use a direct SkiaSharp `[4.150.1]` reference matching the existing resolved dependency version for annotation layout/rasterization, with explicit notice/lock update. The same layout engine rasterizes preview and export; WPF only renders handles. Each text or numbered-callout layer references one FontArtifact. There is no implicit system-font fallback in this version. `IFontArtifactService.CaptureAsync(string fontFile,int faceIndex,CancellationToken ct):Task<FontArtifact>` resolves a selected installed static TrueType/OpenType face; `StageVerifiedAsync(ImmutableArray<FontArtifact> fonts,string privateDirectory,CancellationToken ct):Task<ImmutableDictionary<Guid,string>>` copies/hash-verifies exact files into private staging for both preview/export. `FontTextValidator.Validate(FontArtifact font,string text):ImmutableArray<ValidationIssue>` reports missing glyphs and unsupported shaping before acceptance. Restrict v1 text to left-to-right runs renderable as scalar glyphs in that face; combining/complex-script/RTL shaping, variable fonts and color emoji are explicitly unsupported until a shared shaping implementation is added. Basic CJK is allowed only when glyph coverage passes. No invisible tofu substitution, silent fallback face, downloaded font or font export into user output. Choose another face or revise text when validation fails. A changed/missing font requires explicit re-resolution and new recipe identity. ### Coordinate and time spaces (normative)

- Image source plane S is EXIF-normalized, before user flips/quarter-turns; width/height and masks are in S pixel edges. Plane G is S after those user transforms; ImageGeometry.Crop is in G. Plane C is the cropped/resized image placed into the final canvas. Annotation points/rectangles/font sizes, CanvasSpec.Placement and collage tile rectangles are in final C pixels. Masks are mapped S→G→crop and clipped; their spatial radii are source-pixel units. Overlay rendering maps C→WPF DIPs only for display; pointer edits use the inverse map. No persisted coordinate is a viewport DIP. A canvas resize scales existing annotation coordinates only after an explicit “Scale artwork” choice; otherwise anchors remain in absolute C pixels and clipping is visible.
- Video common canvas V uses first clip's orientation/SAR-normalized display pixels. Per-clip fit maps every clip into V; VideoRecipe.Crop and all TimedMask keyframe bounds are in V. Crop introduces an offset before final output scaling; the compiler maps masks through that same offset/scale. Final encoder even-dimension adjustment is shown as an exact output rectangle before export. Snapshot uses this edited geometry, at full output resolution, and is never secretly the untouched source frame.
- Raw PTS is a signed integer count of that stream's TimeBase (seconds per tick); RawStartPts may be negative or nonzero. MediaSourceInfo.PresentationOrigin is the earliest usable presentation instant across supported non-attached-picture audio/video streams in that source, determined from actual timestamps and fixed for that captured source. Selecting a different stream does not silently change this origin. Missing/unusable timestamp identity is an inspection error for exact frame tools, never an invented FPS index.
- FrameStamp.SourceOffset = RawPts × TimeBase − PresentationOrigin, in normalized source seconds. MediaClip.Range and ReadFrameTimesAsync's sourceRange use this same normalized source timeline, independent of an individual stream's raw start. A stream beginning later retains its positive offset; do not subtract RawStartPts a second time. Probe Frames/ReadFrameTimesAsync return FrameStamp pairs, not ambiguous unlabelled raw-time RationalTime arrays. Initial frame window is at most 4096 stamps; additional windows are requested with explicit stream index and maximumFrames (1..4096). Reject ambiguous/nonmonotonic presentation stamps for exact frame tools rather than guessing ordering; codec decode order is not presentation order.
- The compiler computes each clip's assembled start B as the sum of preceding trimmed durations divided by their speed. A frame with normalized source offset u in clip range [a,b) maps to assembled time B + (u−a)/speed. Clip speed is validated 0.25..4 with at most six decimal places and converted to the exact rational represented by that displayed decimal when doing timeline arithmetic. SplitAt, SnapshotAt, TimedMask times, BleepRegion times, PreviewRequest.Time, PreviewFrame.ActualTime and playback Position use this assembled timeline; they never expose raw source PTS. ActualTime is the selected displayed frame's mapped time, not simply the requested scrub time. FrameIdentity separately carries its source ID/stream/RawPts through MediaGraphPlan into PreviewFrame. A generated visualizer frame has no source-video identity and reports its actual assembled sampling instant.
- Scrubbing chooses the greatest available assembled frame timestamp ≤ requested time within the selected clip; if no such frame exists in that clip, use its first included frame and report its actual later time. Stepping traverses the mapped actual stamps. A snapshot uses that selected identity, verified against the captured source; preview scaling/FFmpeg seek optimizations cannot replace it with a nearby keyframe. Encode time-base quantization occurs only at the encoder boundary and is measured separately; no guessed frame rate can redefine source identity or silently adjust stored ranges.

Concrete nonzero-start/VFR example: video TimeBase=1/90000, RawStartPts=900000 and PresentationOrigin=10 seconds. PTS [900000,903600,909000,920700] become source offsets [0,.04,.10,.23], not [10,10.04,10.10,10.23]. Clip range [.04,.50), speed 2 and preceding assembled duration B=3 map the included frames to [3,3.03,3.095]. Scrub at 3.04 displays raw PTS 909000 with ActualTime=3.03; snapshot exports that same frame at full edited resolution. Clip duration is (.50−.04)/2=.23, so the next clip starts at 3.23 regardless of this clip's VFR gaps. For a negative-origin source with RawStartPts=−4500, TimeBase=1/90000 and PresentationOrigin=−.05, raw PTS 0 has normalized SourceOffset=.05; it is not clamped or shifted to zero.
- PDF source geometry is PDF points (1/72 inch) with page crop/media box and rotation; source→display map translates crop origin, rotates, then flips PDF bottom-left to display top-left and applies DPI/72. Page grid positions are view state; the ordered PdfPageRef array is export order. Duplicate output IDs do not change the referenced source coordinate system.
