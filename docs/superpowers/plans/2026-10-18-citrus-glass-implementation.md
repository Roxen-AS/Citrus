# Citrus Native Glass and Physical Feedback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add real supported Windows Acrylic, an original restrained glass surface treatment and immediate interruptible feedback without changing Citrus's working drag/submission behavior.

**Architecture:** Pure material policy and an analytic critical spring live in Core. Windows owns documented DWM/WinRT adapters, ordinary-window and separately proven wheel-backdrop controllers, one active-only CompositionTarget.Rendering scheduler, and shared material/control resources. The existing layered OLE wheel remains the input owner; glass is a presentation capability with an honest opaque fallback.

**Tech Stack:** .NET 10.0.402, WPF, documented DWM/User32/GDI APIs, Windows.UI.ViewManagement.UISettings, xUnit and interactive Windows compositor evidence. Allow only pinned Windows SDK reference/projection dependencies required for UISettings, including their app-local WinRT.Runtime/Microsoft.Windows.SDK.NET assemblies; no unrelated runtime package, framework migration or conversion/backend download. Task 1 gates the exact locked dependency closure, notices/provenance and published payload inventory.

**Spec:** `docs/superpowers/specs/2026-10-18-citrus-glass-design.md`

## Global Constraints

- Windows 10 22H2/11 x64; native WPF; no framework rewrite, new runtime backend download, undocumented composition API or desktop-as-texture capture.
- Genuine layered OLE wheel HWND, confirmed immutable payload, generation/arming/paging/drop/cancel ownership and fixed visible target geometry remain unchanged.
- Backdrop HWNDs never activate, receive keyboard focus, register OLE, capture pointer input, or outlive their visible surface. Unconfirmed candidates never show a backdrop or material shell.
- Windows high contrast or disabled transparency effects always uses opaque accessible materials; user ReduceTransparency also forces opaque materials. Reduced motion is independent from transparency and sound.
- One application CompositionTarget.Rendering subscriber exists only while spring channels are active; no perpetual idle animation loop or animated software blur.
- RenderTargetBitmap is WPF-layer evidence only. Actual OS backdrop requires native compositor capture over an owned background, or explicitly pending manual Windows 11 evidence.
- Preserve actual N≤9, 750-ms admission timeout, 8-DIP arming, 400-ms page dwell, 45-ms selection-sound throttle, SoundEnabled=true default and post-OLE dispatch. No product routes or conversion/editor foundation changes.

## Review Focus

- A nonlayered helper owned by the wheel would be forced above it; a disabled correctly owned helper must stay behind the real OLE surface and never take input (Task 1).
- Confirm/cancel/reopen and stale render callbacks must not expose bare frosting, hide a new generation, or strand a native helper (Tasks 1,3,4).
- Windows transparency/high-contrast/RDP changes and fractional/mixed DPI must synchronously fall back or reposition safely without changing wheel hit geometry (Tasks 1,3,4).
- Fast pointer-down/up/down must preserve present value/velocity and immediate feedback; all spring callbacks must stop after settle/unload/quit (Task 2).
- A screenshot can contain only WPF even when native Acrylic is configured; evidence must prove live owned-background frosting and label raster scaling versus actual monitor DPI (Task 4).

**Interfaces:** CriticalSpring.Advance/Retarget/IsSettled; SpringAnimator.Retarget(owner,channel,target,parameters,apply), SetImmediate(owner,channel,value,apply), CancelOwner(owner,settle), Dispose, internal AdvanceAt(stopwatchTimestamp). SetImmediate(object owner,string channel,double value,Action<double> apply):void sets Value=Target=value and Velocity=0, cancels any active response for that channel and applies synchronously before first retarget, matching the spec. Settlement applies the exact target, zeros velocity and removes the channel from the active set while retaining its settled value for future retargets; last active settlement unsubscribes Rendering. CancelOwner/Dispose also remove retained state. CancelOwner(settle:true) applies targets before removal; false removes without another apply; Dispose removes without calling destroyed visuals. There are no completion/hide callbacks: native window hiding stays synchronous. PressFeedback.IsEnabled attaches to ButtonBase, preserving normal Click/release/cancel semantics. Inheritable attached `PressFeedback.Animator:SpringAnimator?` exposes `GetAnimator(DependencyObject):SpringAnimator?` and `SetAnimator(DependencyObject,SpringAnimator?):void`. App sets one shared scheduler on each window root; null gives normal synchronous press fill/edge feedback only, with no Startup/service-locator dependency or per-control Rendering handler. Tests assign a deterministic scheduler explicitly. Unloaded/scheduler replacement cancels that button owner on the old scheduler and restores template state.
