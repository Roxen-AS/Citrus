# Citrus Functional Editors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace numeric-only tools with actual image, media and PDF editors whose verified exports use the existing local conversion queue.

**Architecture:** Versioned immutable documents feed one family renderer/graph for both previews and exports. Family engines adapt documents to the existing queue and collision-safe writer; WPF editors own interaction/undo, never conversion execution. Each task below adds a tested boundary or usable vertical slice; Office and automatic detection remain separately declared acquisition projects.

**Tech Stack:** .NET 10.0.402, WPF, current pinned Magick.NET 15.0.0, owned FFmpeg 9.0.2, PDFsharp 6.2.4, PDFtoImage 5.4.0, PdfPig 0.1.16, SkiaSharp 4.150.1 promoted from the existing lock to direct pinned dependency, xUnit and Windows CI. Use an owned WASAPI adapter for preview audio; do not assume installed playback codecs.

**Spec:** `docs/superpowers/specs/2026-10-18-citrus-editors-design.md`

## Global Constraints

- Windows 10 22H2/11 x64; .NET 10.0.402 and native WPF; offline processing; no runtime engine/model downloads.
- Originals remain unchanged; export uses collision-safe `OutputWriter`; no preview writes into the user's output directory.
- Preview and export compile the same immutable recipe and operation order; export always renders from verified source copies, never the viewport bitmap.
- Core recipes contain no WPF objects, mutable lists, arbitrary command strings, or decoder handles. Schema version 1; explicit allowlisted JSON discriminators; unknown versions/types fail visibly.
- Opening, previewing, undoing and canceling an editor never enqueue work. Export queues a frozen document once; subsequent edits cannot change that job. Retry uses the same frozen recipe and verified sources.
- Every visible enabled control changes a genuine preview, recipe or output. Missing capabilities remove the corresponding action and explain why; no synthetic waveform, guessed file size or successful placeholder inference.
- Existing scalar operations, immutable drag payload and post-OLE callback behavior remain valid. This subproject does not alter wheel petal counts, drag geometry or feedback defaults; the parent interface project owns dynamic actual-N petals up to nine per page and sound enabled by default.
- No OCR/face/ASR/subject-removal/Office placeholder routes; honor the spec's explicit acquisition gates and honest output/fidelity limits.

## Review Focus

- A source replaced with same length/mtime must fail hash verification; an in-flight old preview may not overwrite the latest edit (Tasks 1–2).
- EXIF rotation, zoom/DPI changes and mixed image aspect ratios must preserve crop/mask/annotation alignment in full-resolution output (Tasks 2–4).
- Variable-frame-rate/nonzero-start/silent clips and missing PNG/lavfi capabilities must not yield wrong snapshot frames, drifting splits or fake playback (Tasks 6–8).
- Nonmonotonic codec sizes and already-compressed inputs must not report a target hit when measured bytes exceed it; cancel/late failures must not leak staged files (Tasks 5,9,11).
- Rotated/cropped PDF boxes, duplicate source pages and cross-page links must export the visible order/rotation or disclose unsupported feature loss (Tasks 10–11).

## File map and execution rules

All contract names/fields/signatures are authoritative in the spec. Core files live in `src/Citrus.Core/Editing`, renderers in `src/Citrus.Conversion/Editing`, WPF views in `src/Citrus.Windows/Editors`; do not put new family engines into `ToolOptionsWindow.xaml.cs` or one giant editor class. Use one corresponding fixture-focused test class per listed test file. Data fixtures go in `tests/Fixtures/Editors/{Image,Media,Pdf}` with generator/provenance notes, small source artifacts and deterministic expected values; never download fixtures during tests.

Tasks are sequential at shared boundaries; do not dispatch concurrent edits to Models/Registry/App without a separate integration owner. Each task ends with a focused commit and short report. No executable implementation bodies appear in this plan; named assertions specify the intended red/green behavior. Host tests are meaningful but do not replace Windows native execution.

Default verification commands, selecting only the relevant named classes in each task:

- Core: `dotnet test tests/Citrus.Core.Tests/Citrus.Core.Tests.csproj -c Release --filter FullyQualifiedName~<Class>`.
- Conversion: `dotnet test tests/Citrus.Conversion.Tests/Citrus.Conversion.Tests.csproj -c Release --filter FullyQualifiedName~<Class>`.
- Windows: `dotnet test tests/Citrus.Windows.Tests/Citrus.Windows.Tests.csproj -c Release --filter FullyQualifiedName~<Class>` on Windows.
- Cross-build: `dotnet build Citrus.sln -c Release -p:EnableWindowsTargeting=true --no-restore` after normal locked restore. Native test execution unavailable on Linux is reported as unrun, not green.
- Adding the direct Skia reference intentionally updates only the relevant lock entries, then `dotnet restore Citrus.sln --locked-mode -p:EnableWindowsTargeting=true` must pass. No general dependency upgrades.
