# Contributing to Citrus

Check existing issues before opening a report or proposing a large change. For a bug, include version, Windows build, display scale, steps and a small non-sensitive sample. For a feature, explain the file task and expected result. Do not attach private documents, credentials or unredacted desktop recordings.

Read [development setup](docs/DEVELOPMENT.md), [operations](docs/operations.md) and [preview notes](docs/PREVIEW-NOTES.md). Preserve originals, source verification, collision-safe publication, cancellation, accessibility fallbacks and the accepted wheel/white-menu design. Do not weaken path/format validation to make a fixture pass.

Keep changes focused and add meaningful regressions. Explain the change, checks actually run and remaining limits. Native Explorer behavior, visual matching, performance, engine acquisition and clean-machine installation need separate evidence.

Application contributions use MIT. Do not submit binaries, photography or dependencies without rights, sources, licenses and provenance. Third-party components keep their licenses.
